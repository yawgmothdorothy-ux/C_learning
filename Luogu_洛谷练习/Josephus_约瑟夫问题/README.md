# P1996 约瑟夫问题：多次死循环的错题记录

日期：2026-10-10。本题已经通过提交。本笔记记录尝试过程中出现的问题，帮助以后判断循环为什么不结束，而不是只记住最后能运行的代码。

自己的实现保留在 [P1996.c](P1996.c)，独立的参考版本见 [P1996_reference.c](P1996_reference.c)。

## 1. 问题与模拟方式

`n` 个人按编号 `1..n` 围成一圈，从 1 号开始报数，起点算 1。每次数到 `m` 就淘汰当前人，下一人重新从 1 报数。输出所有人的淘汰顺序。

固定编号不变，数组只记录是否在场：`p[index] = 1` 表示在场，`0` 表示淘汰。数组位置从 0 开始，因此编号是 `index + 1`。

```text
位置：0 → 1 → 2 → 3 → 4 ─┐
      ↑                  │
      └──────────────────┘
编号：1   2   3   4   5
```

“环形”只意味着位置走过最后一人后回到开头。淘汰者仍占据原来的位置，但经过他时不报数。

以 `n = 5、m = 3` 为例：

| 当前编号 | 当前状态 | 报数变化 | 结果 |
| --- | --- | --- | --- |
| 1 | 在场 | 0 → 1 | 继续 |
| 2 | 在场 | 1 → 2 | 继续 |
| 3 | 在场 | 2 → 3 → 0 | 淘汰 3 |
| 4 | 在场 | 0 → 1 | 继续 |
| 5 | 在场 | 1 → 2 | 下一位置绕回 1 |
| 1 | 在场 | 2 → 3 → 0 | 淘汰 1 |
| 2 | 在场 | 0 → 1 | 继续 |
| 3 | 已淘汰 | 保持 1 | 跳过 |
| 4 | 在场 | 1 → 2 | 继续 |
| 5 | 在场 | 2 → 3 → 0 | 淘汰 5 |

继续模拟会得到完整顺序 `3 1 5 2 4`。绕回开头不重置报数，只有发生淘汰时才重置。

## 2. 每个变量只负责一件事

| 自己代码中的名字 | 含义 | 初始值 | 更新时机 | 判断标准 |
| --- | --- | --- | --- | --- |
| `n` | 总人数、固定位置数量 | 输入值 | 不改变 | 编号位置范围依据最初人数，不依据剩余人数 |
| `m` | 每轮淘汰的报数标准 | 输入值 | 不改变 | 这是题目规则，不是循环计数器 |
| `count` | 累计经过的位置数 | 0 | 每轮处理完当前位置后加 1 | 无论当前位置是否在场，都必须向前走 |
| `count % n` | 当前数组位置 | 0 | 随 `count` 移动 | 值必须在 `0..n-1` 内 |
| `m_counter` | 本轮有效报数 | 0 | 在场的人报数时加 1；淘汰后归零 | 它数的是人，不是经过的位置 |
| `person` | 剩余人数 | `n` | 真正淘汰一个在场的人后减 1 | 不能因为移动或普通报数而减少 |
| `p[index]` | 当前人的存活状态 | 全部为 1 | 淘汰时从 1 改为 0 | 已淘汰的人不能再次报数或减少剩余人数 |

决定变量何时增减之前，先用一句话描述“它在数什么”。位置数、报数、淘汰人数代表三个不同的事件，不能用一个计数器替代。

## 3. 多次卡死分别发生在哪里

### 第一次：把报数和位置混在一起

最初的草稿里，`count` 没有初始化，没有明确的位置移动逻辑，却修改了固定规则 `m`，并在未发生淘汰时减少剩余人数。

这时变量没有清晰含义，不能只靠添加取模来修复。先明确上一节的职责，再把每个更新绑定到对应事件。

### 第二次：停在刚淘汰的位置

当报数达到 `m` 时，程序标记淘汰并清零报数，但没有移动当前位置。下一轮仍停在这个已淘汰者上。

```text
当前人已淘汰 → “在场”条件不满足
报数已经归零 → “达到 m”条件不满足
没有分支执行 → 所有状态保持原样 → 永远重复
```

修正标准：每轮都移动一次，不把位置移动只放在“在场的人”分支里。

### 第三次：跳过淘汰者的条件写错

错误表达式是 `p[count % n == 0]`。它先计算 `count % n == 0`，得到 0 或 1，再访问 `p[0]` 或 `p[1]`。

真正要判断的是 `p[count % n] == 0`，也就是“当前位置是否已淘汰”。

此外，当时又要求 `m_counter != 0` 才跳过。报数刚归零时遇到淘汰者，就无法移动。跳过淘汰者不应依赖当前报数。

### 第四次：报数到 m 后，被外层条件挡住

某次把 `m_counter++` 放在淘汰判断之后，外层仍要求 `m_counter != m`：

```text
进入分支时：报数 != m
立即判断：报数 == m       ← 中间没有更新，所以不可能成立
之后才加 1
达到 m 后：下一轮进不了分支，再也没有机会淘汰或归零
```

剩余人数不再减少，当前位置虽然一直移动，程序仍然永远不结束。这说明“有变量变化”不等于“循环一定能终止”。

修正标准：进入在场分支后，先报数加 1，再判断是否淘汰。外层只需判断是否在场。

### 第五次：报数初值为 1，遇到 m = 1 卡死

代码先检查报数不等于 `m` 才允许进入分支。如果报数初值为 1，而输入 `m = 1`，程序从一开始就不让任何人报数或淘汰。

曾经用 `m == 1` 特殊分支绕过这个情况。但按“初值 0 → 当前人报数加 1 → 达到 m 就淘汰”的顺序，自然就能处理 `m = 1`，不必特殊处理。

## 4. 没卡死也不代表答案正确

### 输出加 2，只是掩盖了第一次报数提前的问题

报数初值为 1，又先加 1，导致第一次淘汰提前一人。把输出改成 `(count + 2) % n`，会显示另一个编号，但实际标记淘汰的位置没有改变。

输出表达式不会影响循环是否结束；此前不再卡死，是因为补上了位置移动。

当时输入 `5 3` 得到 `3 1 0 2 4`，输入 `6 3` 得到 `3 0 4 2 5 1`。编号出现 0 已经说明输出映射有问题。

正确对应关系是：数组位置 `count % n`，选手编号 `count % n + 1`。先取模，再加 1。

### 输出应该发生在移动位置之前

淘汰当前人后，若先移动位置再输出，会打印下一人的编号。先输出被淘汰者，再移动到下一位置。

### 多个数字之间要有分隔符

`m == 1` 的一个版本输出了 `12345`，而题目需要的是编号序列 `1 2 3 4 5`。大于 9 的编号尤其不能省略分隔符。

## 5. 循环体的固定顺序

```text
while：还有人在场
    检查当前位置
    如果此人在场：
        报数加 1
        如果报数达到 m：
            输出当前人的编号
            标记淘汰
            剩余人数减 1
            报数归零
    无论是否在场，都移动到下一个位置
```

一次循环只处理一个位置。淘汰者不报数，但不会阻止位置向前移动。

可以在每轮开始时检查这些状态约束：

- 剩余人数等于存活标记为 1 的人数。
- 当前数组位置在 `0..n-1` 内。
- 当前报数满足 `0 <= m_counter < m`。
- 只有在场的人才能被淘汰，人数不能因同一个淘汰者重复减少。

这里的报数上限约束适用于“每轮开始时”：本轮报数可能暂时达到 `m`，但应立即淘汰并归零。

## 6. 为什么这里适合 while，怎样判断它会结束

`for` 和 `while` 都能写这个问题。`for` 常用于明确的遍历或统一步进；`while` 适合直接表达“只要还有人，就继续处理”。

本题人数 `n` 固定，淘汰总共发生 `n` 次，但实际扫描位置的次数不固定，因为绕圈会经过已淘汰者。

证明它会结束不能只看 `count++`，而要看最终结束条件依赖的 `person`：

1. 每轮都移动位置，所以只要有人在场，就一定会继续遇到在场的人。
2. 每遇到一个在场的人，报数增加，有限次有效报数后一定达到正整数 `m`。
3. 达到 `m` 就淘汰一人，剩余人数严格减少。
4. 剩余人数从 `n` 开始，最多淘汰 `n` 次后到 0，循环结束。

如果卡住，先区分两种情况：完全没有变量变化；位置一直变化，但结束条件依赖的人数不再减少。后者也是死循环。

调试时建议逐步记录“当前位置、存活状态、报数、剩余人数”，看它们是否符合上面的更新规则。终端能输入文字，不代表程序正在调用 `scanf`；输出缺少换行，也可能暂时留在缓冲区里，让死循环看起来像等待输入。

## 7. 一份更清晰的参考写法

[P1996_reference.c](P1996_reference.c) 使用同样的存活标记模拟，但做了四个简化：

- `pos` 只保存当前位置，不无限累加，避免长期扫描时累计计数溢出。
- 报数从 0 开始，外层只检查是否在场。
- 位置移动统一放在循环末尾，没有两个分支重复写移动。
- 不单独处理 `m == 1`，同一套逻辑覆盖所有正整数 `m`。

这是减少出错机会的写法，主要改进结构与可读性，没有把逐个扫描改成更快的算法。自己的过关版本仍保留，方便对照。

```c
#include <stdio.h>

int main(void) {
    int n, m;
    if (scanf("%d %d", &n, &m) != 2 || n <= 0 || m <= 0) {
        return 0;
    }

    int alive[n];
    for (int i = 0; i < n; i++) {
        alive[i] = 1;
    }

    int pos = 0;        // 当前访问的位置，始终在 0..n-1 内。
    int reported = 0;   // 本轮已经报出的数。
    int remaining = n;  // 尚未淘汰的人数。

    while (remaining > 0) {
        if (alive[pos]) {
            // 只有在场的人报数；先报数，再检查是否淘汰。
            reported++;
            if (reported == m) {
                // 先输出当前人的编号，再标记淘汰。
                printf("%d%c", pos + 1, remaining == 1 ? '\n' : ' ');
                alive[pos] = 0;
                remaining--;
                reported = 0;
            }
        }

        // 无论是否在场，每轮都移动一次；绕圈不会重置报数。
        pos = (pos + 1) % n;
    }

    return 0;
}
```

如果以后需要优化，可以维护“仍在场的编号列表”，直接计算下一次淘汰在列表中的位置：`(起点位置 + m - 1) % 剩余人数`。记录并删除该位置后，从补到此位置的下一人继续。这样能跳过完整报数过程，但数组删除需要移动后续元素，总体可做到 O(n²)。本次先把逐步模拟和循环状态理解清楚。

## 8. 验证与运行

| 输入 | 期望淘汰顺序 | 检查内容 |
| --- | --- | --- |
| `5 3` | `3 1 5 2 4` | 普通淘汰、跳过淘汰者和绕圈 |
| `5 1` | `1 2 3 4 5` | 每个在场的人立即淘汰 |
| `1 3` | `1` | 只有一个人，也可以报满 3 次 |
| `6 3` | `3 6 4 2 5 1` | 编号不能出现 0 |
| `5 8` | `3 2 5 4 1` | 报数长度超过人数 |
