# P1996：从数组模拟到链表与队列

日期：2026-10-11。题目：[洛谷 P1996 约瑟夫问题](https://www.luogu.com.cn/problem/P1996)。

`n` 个人编号为 `1..n`，从 1 号开始报数，报到 `m` 的人出圈，下一人重新报 1，输出全部出圈顺序。这里从本目录已有的数组模拟出发，学习两种新的组织方式。

## 1. 先分清概念

**链表（linked list）**把数据放在节点（node）中，每个节点还保存下一个节点的地址 `next`。访问下一个人靠链接，而不是数组下标加 1。

```text
普通单链表：1 → 2 → 3 → NULL（结束）
循环单链表：1 → 2 → 3 → 1 → ……（尾节点连接首节点）
```

节点不要求在内存中相邻。想访问第 k 个节点，通常要从起点逐个走过去，耗时 O(k)。已经知道待删节点及其前驱时，摘掉节点只需修改一个链接，耗时 O(1)；寻找它的时间要另算。

**队列（queue）**规定操作顺序为先进先出（FIFO，First In, First Out），就像排队：先来的人先离开。入队（enqueue）在队尾，出队（dequeue）在队头。

```text
出队 ← [1, 2, 3, 4, 5] ← 入队
        队头        队尾
```

队列可以用数组实现，也可以用链表实现。因此，“链表”和“队列”关注的层面不同：前者关注节点如何连接，后者关注允许怎样存取数据。

**循环队列（circular queue）**是数组实现队列的一种方式：下标走到末尾就回到开头，重复使用已出队元素腾出的空间。它仍然遵守先进先出。

| 方式 | 存什么 | 如何处理淘汰者 |
| --- | --- | --- |
| 原来的数组标记 | 每个编号是否在场 | 标记为 0，以后经过时跳过 |
| 循环链表 | 编号及下一人在何处 | 改链接，以后不会再经过他 |
| 循环队列 | 按报数顺序排列的在场编号 | 出队后不再放回 |

## 2. 链表解法：把仍在场的人直接连起来

带完整注释的 C 代码：[P1996_linked_list.c](P1996_linked_list.c)。

节点定义：

```c
typedef struct Node {
    int id;
    struct Node *next;
} Node;
```

`Node` 是结构体类型的别名；`Node *current` 是指向节点的指针；`&nodes[i]` 取节点地址；`current->id` 访问指针所指节点的编号，等价于 `(*current).id`。结构体里的 `next` 使用 `struct Node *`，因为此时末尾的别名 `Node` 还没定义完成。

维护两个指针：`current` 指向本轮开始报数的人，`previous` 指向他的前驱。初始 `current` 指向 1，`previous` 指向 n。

以 `5 3` 为例：起点 1 报 1，前进到 2 报 2，再前进到 3 报 3。因此每轮要走 **m-1 步**，不是 m 步。

```text
删除前：1 → 2 → 3 → 4 → 5 → 1
此时 previous 指向 2，current 指向 3。

执行 previous->next = current->next：
删除后：1 → 2 ─────→ 4 → 5 → 1
下一轮 current = 4，previous = 2。
```

整个过程：

| 轮次 | 本轮报数起点 | 出圈者 | 下一轮起点 |
| --- | --- | --- | --- |
| 1 | 1 | 3 | 4 |
| 2 | 4 | 1 | 2 |
| 3 | 2 | 5 | 2 |
| 4 | 2 | 2 | 4 |
| 5 | 4 | 4 | 结束 |

实现把节点统一放在 `Node nodes[n]` 里，节点内的真实指针负责连接。数组负责提供存储，链表负责规定遍历顺序；这仍然是链表。出圈时只从环上摘掉节点，其存储到 `main` 结束才失效，没有单独调用 `malloc/free`。

## 3. 队列解法：报过数的人移到队尾

带完整注释的 C 代码：[P1996_queue.c](P1996_queue.c)。如果刚接触指针，建议先看这一版。

队头始终是接下来报数的人。前 m-1 人各出队一次，再入队一次；第 m 人只出队，输出他的编号。

以 `5 3` 为例，每行左侧都是队头：

```text
[1, 2, 3, 4, 5]  初始
[2, 3, 4, 5, 1]  1 报 1，移到队尾
[3, 4, 5, 1, 2]  2 报 2，移到队尾
[4, 5, 1, 2]     3 报 3，出队淘汰，输出 3
[5, 1, 2, 4]     4 重新报 1，移到队尾
[1, 2, 4, 5]     5 报 2，移到队尾
[2, 4, 5]        1 报 3，出队淘汰，输出 1
```

关键变量：`head` 是下一次出队的位置；`tail` 是下一次入队的位置；`size` 是队列中的人数。代码约定的 `tail` 不是“最后一个元素的位置”。

数组容量始终是初始人数 `n`，所以下标更新使用 `(head + 1) % n` 和 `(tail + 1) % n`，不能把这里的 n 换成不断减少的 size。

最初队列装满，`head == tail == 0`；最后队列为空，也可能 `head == tail`。本实现用 `size == n` 判断满，用 `size == 0` 判断空，允许全部 n 个位置都存人。满队列转动时先出队腾出位置，再入队，不会覆盖尚未处理的人。

## 4. 为什么都可以取模，复杂度是多少

剩 r 人时，走 r 步或让 r 人依次出队再入队，都会回到相同的起点及顺序。所以两份代码都把每轮的 m-1 次移动缩减为：

```c
int steps = (m - 1) % remaining; // 队列版 remaining 对应 size。
```

注意：取模的是“移动次数”，不能先对固定 n 改写 m。每次淘汰后，圈中的人数都会改变。

每轮移动次数不超过 `m-1`，也不超过 `r-1`。含初始化和输出，两份实现的时间上界都是 **O(n × min(m, n))**，最坏为 O(n²)，额外空间都是 O(n)。固定较小的 m 时为 O(nm)。若不使用取模，直接每轮模拟 m 次，则为 O(nm)，m 很大时会做许多无用的整圈移动。

已知前驱的链表删除是 O(1)，数组循环队列的一次入队/出队也是 O(1)，但找第 m 人需要移动，因此不能说整个算法是 O(n)。

只求最后幸存者时，可用零起点编号递推 `f(1)=0`、`f(r)=(f(r-1)+m)%r`，最终编号为 `f(n)+1`。本题要求全部出圈顺序，不能只输出这个结果。

## 5. 编译和验证

在本目录中运行，两份程序独立编译，选择任意一份提交即可：

```bash
gcc -std=c99 -Wall -Wextra -Wpedantic P1996_linked_list.c -o /tmp/P1996_linked_list
gcc -std=c99 -Wall -Wextra -Wpedantic P1996_queue.c -o /tmp/P1996_queue
printf '5 3\n' | /tmp/P1996_linked_list
printf '5 3\n' | /tmp/P1996_queue
```

| 输入 | 期望输出 | 重点 |
| --- | --- | --- |
| `5 3` | `3 1 5 2 4` | 绕圈及起点更新 |
| `5 1` | `1 2 3 4 5` | 不移动，直接淘汰队头或当前节点 |
| `1 3` | `1` | 最后一人也输出 |
| `6 3` | `3 6 4 2 5 1` | 多轮删除 |
| `5 8` | `3 2 5 4 1` | m 大于人数，跳过整圈 |

验证结果：两份新增实现均使用严格编译选项通过编译，无警告；分别与独立的“存活列表按位置删除”模拟核对 703 组输入。覆盖 `n=1..20、m=1..30` 的 600 组组合，另加 100 组固定随机种子的输入和 3 组边界输入，包括 `n=100、m=2147483647`。测试启用了 UBSan，未报告未定义行为。这些是本地验证结果，新增版本尚未提交洛谷。
